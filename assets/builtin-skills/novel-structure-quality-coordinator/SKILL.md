# 结构设计与审稿质检

## 与 KeepCompose 文档协议对齐

结构设计不是凭空产出方案，而是协助维护三级大纲与追踪表：

| 层级 | 文件 | 管什么 | 不管什么 |
|---|---|---|---|
| 全书 | 小说资料/03-全书大纲.md | 核心承诺、重大转折、结局方向 | 不锁死几百章细节 |
| 分卷 | 小说资料/04-分卷大纲.md | 阶段故事、阻力与回应、高潮、成果兑现、卷末新局面 | 不规定固定卷长 |
| 滚动 | 小说资料/05-滚动细纲.md | 接下来 5—12 章的场景、篇幅重点、伏笔编号 | 不预写整章对白 |

**卷长与章数服从事件，不设硬性配额。**体量参考（不是规则）：单卷完结 30—50 万字常见 3—5 卷；超长篇 6 卷起、卷内可分篇、70% 进度开始埋终局伏笔。用户明确要求的体量安排优先。

滚动细纲剩余不足 3 章时提醒续补：先列计划细排的章节范围与依据，用户确认后写入。

## 结构设计流程

1. 读 00-项目状态、01-开书定位、02-核心设定（没有则先补开书材料，见 novel-writer）。
2. 确认需求：全书级 / 分卷级 / 滚动级 / 命名 / 伏笔规划。信息不完整只补问最少必要问题。
3. 产出草案在对话中给用户过目，确认或修改后再写入对应文件（格式优先：保持文件现有结构，节内追加/替换）。
4. 伏笔一律登记 F 编号进 追踪-伏笔.md：内容、首现章节、预计回收条件、状态。规划时给出埋设与回收路径；回收后改状态，不删条目。
5. 章名与卷名要有信息量（指向事件或悬念），不空泛（「新的开始」「转折」不合格）。

### 开书大纲自检（写第一章前一次）

沿具体事件核对：因果链是否成立、信息揭示节奏、前三章看点、人物主动性、长期变化空间。问题先修候选；自检状态与未决项写入 00-项目状态「开书大纲自检」节。不每章重跑。

## 审稿质检（报告制）

**只出报告，不直接改稿。**需要动用户的文字时用 question 工具征得确认（KeepCompose 铁律）；AI 自己的初稿可直接修。

按三层检查，优先级从高到低：

1. **篇章级（最优先）**
   - 设定冲突：与 02-核心设定、追踪表、已采用正文矛盾
   - 逻辑断裂：说三缺一、因果跳步、动机悬空
   - 状态连续：伤势/持物/位置/知情/资源变化后是否仍有效（对照 追踪-角色状态、追踪-资源与权限）
   - 伏笔：新埋伏笔是否登记 F 编号；已回收伏笔是否被重复使用；废弃设定是否被恢复（对照 追踪-废弃设定）
   - 章尾钩子：是具体局面还是抽象总结
2. **句段级**
   - 指代断裂、时序跳跃、场景突变、同段视角切换
   - 数量不一致（人数、金额、时间与追踪表对不上）
   - 句式重复、模式化表达（表达层细节移交 novel-deslop 清单）
3. **字词级**
   - 错别字、漏字、多字、错误组词：置信高列出修正建议，置信低标 [待确认]

### 报告格式

```
## 审稿报告 - <对象>
- 结论：通过 / 需修订 / 有硬伤（一句话）

| # | 层级 | 位置（短引≤20字） | 问题 | 依据（文件+条目） | 最少修正建议 |
|---|---|---|---|---|---|

- [待确认]：…
- 需要用户决定的事项：…（用 question 提出）
```

不打分、不统计指标凑数；没有问题的层如实写「未发现」。

## 边界

- 结构问题归本技能；AI味/表达问题归 novel-deslop；两者同时发现分开列。
- 质检发现的问题涉及事实修改（数量、状态、时间线）→ 修正建议须注明来源章节，采纳后按增量回写规则更新追踪表。
- 不用质检报告冒充创作：用户要结构就给结构，要质检就给质检，不强行捆绑。
- 长文本分批处理，但硬伤（设定冲突、逻辑断裂、状态回退）不得遗漏。
