# OpenWrite v2.0.1 去付费 / 去后端改造 —— 可行性评估

> 目标：产出「去掉付费墙与后端服务器依赖、保留全部本地功能」的软件本体（Windows + Android）。
> 评估日期：基于本机静态侦察实测，非推断。
> 结论：**做得到**。三条路径可选，推荐 L0+L1 组合。

---

## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 能不能做到？ | **能**。业务逻辑 100% 在 Dart AOT 层，无壳无混淆、符号表虽剥离但结构完整（aotopsy 实测 `Support: OK`）。 |
| 最短路径多久？ | 数十分钟（改本地配置 + 断刷新）。 |
| 最干净路径？ | 数小时～一天（AOT 二进制补丁 + 重打包 + 重签名）。 |
| 最大风险点 | 会员状态是**多字段联合判定**（vip_status / expire_time / is_lifetime / device_limit / device_count），单点改真会导致 UI 状态不一致。 |
| 最大坑 | 你提供的安装包版本（2.0.1）与 `S:\dsh\OpenWrite` 已装版本（2.0.0）**不是同一份二进制**。 |

## 1. 侦察已确认的硬事实

### 1.1 两端同源，业务全在 Dart 层

| 端 | 业务代码 | 格式 | 大小 |
|---|---|---|---|
| Windows | `data/app.so` | ELF64 x86-64 | 13,058,992（2.0.0）／13,091,760（2.0.1） |
| Android | `lib/arm64-v8a/libapp.so` | ELF64 arm64 | 11,535,280 |

两端 `.so` 里的硬编码常量**逐条一致**（同一套 URL、同一批池字符串），确属同一 Flutter 工程的两份构建。

Java/Kotlin 层极薄：只有 `MainActivity`（`com.openwrite.app/updater` channel，`installApk`）与 `R`。→ **改造点全在 AOT 快照，不需要碰 Java。**

### 1.2 构建配置（aotopsy `doctor` 实测）

```
Dart:        3.11.0
Pointers:    uncompressed (8 bytes)
Features:    product no-code_comments dwarf_stack_traces_mode
             dedup_instructions no-asan no-msan no-tsan
             no-shared_data x64 windows no-compressed-pointers
```
**无 `obfuscate`**。符号名是 release 剥离 `.symtab` 的结果，不是混淆。

### 1.3 代码规模（aotopsy `signal` 实测）

```
instructions : 26564（21316 stub + 5248 real code）
classes      : 4355 layouts
scripts      : 1161 / library_functions 938
pool         : 76641 entries
```

### 1.4 内存布局（补丁可行性基础）

ELF program headers 中 **PT_LOAD[1] 的 vaddr == file offset == 0**，因此文件偏移即虚拟地址，可直接用十六进制编辑器定位。

Dart 线程寄存器约定（`dart_meta.json` 实测）：

```
R14 = THR
  [R14+0x80] = null
  [R14+0x90] = bool_false
  [R14+0x98] = bool_true
  [R15]      = 对象池 (PP) 基址
```

x64 上布尔常量加载指令统计（全 `.text` 扫描）：

```
MOV r64,[R14+0x90]  false : 7027 处   ← 1 字节改成 0x98 即变 true
MOV r64,[R14+0x98]  true  : 8225 处
MOV r64,[R14+0x80]  null  : 33884 处
```

**结论：布尔返回值翻转是 1 字节补丁，机械上完全可行。**

### 1.5 字符串对象布局（已字节级验证）

Dart AOT x64 的 OneByteString 对象头 **24 字节**：

```
+0x00  tags       (8B, 快照中为 0)
+0x08  hash_      (4B)
+0x0C  padding    (4B)
+0x10  length_    (8B, Smi 编码：值 = 字节数 << 1)
+0x18  字符数据
```

验证样本（`is_vip` 字符数据 @ 0x289720）：

```
tags   = 0x0000000000000000
       = 0x08e846100005e272
length = 0xc  →  Smi 解码 6  ✓ 与 "is_vip" 长度吻合
```

`vip_status` → length=0x14 → Smi 10 ✓；`need_vip` → length=0x10 → Smi 8 ✓。
**对象 VA = 字符数据偏移 − 24。**

## 3. 会员判定链（改造靶点）

### 3.1 本地状态 100% 落在 shared_preferences

实测本机 `%APPDATA%\com.openwrite\OpenWrite\shared_preferences.json`：

```json
"flutter.vip_phone":        "15854735859",
"flutter.vip_status":       false,
"flutter.vip_days_left":    0,
"flutter.vip_expire_time":  "2026-06-10 21:34:17",
"flutter.vip_is_lifetime":  false,
"flutter.vip_device_limit": false,
"flutter.vip_device_count": 0,
"flutter.vip_last_check":   "2026-09-27T08:45:20.946798"
```

**这就是完整的会员状态面。** 后端只在 `vip_last_check` 时刷新它。

### 3.2 AOT 中 26 个相关函数（aotopsy `string_refs` 实测）

| 函数 | 角色（按引用的键推断） |
|---|---|
| `sub_6eb6e4` (0xbae2a4) | **核心判定**：读 `is_vip` / `device_limit` / `device_count` / `current_devices` / `device_id` / `phone` / `timestamp` |
| `sub_6ecd38` (0xbaf8f8) | **写状态**：写 `vip_status` / `vip_expire_time` / `vip_is_lifetime` / `vip_days_left` / `vip_device_limit` / `vip_device_count` / `vip_phone` / `vip_last_check` |
| `sub_6ecf44` | 同上（另一入口，疑为后端回包解析） |
| `sub_736280` | 同上（疑为启动时校验） |
| `sub_739ce0` (0xbfc8a0) | **need_vip 闸门**，调用 `sub_70e06c` |
| `_qua@368426794.dPb_73963c` (pc 0xbfc6ad) | need_vip 引用点 |
| `_kC@23065589._Tuc@23065589_7448a0` (pc 0xc07a82) | need_vip 引用点 |
| `sub_70e06c` | 被 9 个函数调用，**疑为"检查 VIP 否则弹窗/拦截"的统一入口** |
| `sub_7458e4` / `sub_747604` / `sub_7481a8` / `sub_749208` / `sub_749ef8` / `sub_70f2d0` / `sub_70f7b8` / `sub_70d0e4` | 各功能页的 VIP 门（均引用 `member_type`） |

**关键洞察**：`sub_70e06c` 是收敛点——9 个不同功能页的 VIP 门全部汇到它。**这是最高杠杆的单点改造目标。**

### 3.3 高风险提示

`sub_6ecd38` 一次性写 8 个 `vip_*` 键。若只改 `vip_status=true` 而 `vip_expire_time` 仍过期，UI 会进入"VIP 但已过期"分支；若 `vip_device_count=0` 而 `vip_device_limit=true`，设备管理页会渲染空列表。

→ **正确做法是让 `sub_6ecd38` 整体走 "lifetime vip" 分支**，而不是只翻一个布尔。

## 4. 三条路径

### L0 — 配置层（最短，无二进制改动）

**做法**
1. 备份并改写 `shared_preferences.json`：
   ```
   vip_status      → true
   vip_is_lifetime → true
   vip_expire_time → 2099-12-31 23:59:59
   vip_days_left   → 36500
   vip_device_limit→ true（可选，解锁多设备）
   vip_device_count→ 1
   vip_last_check  → 远期时间戳（阻止触发刷新）
   ```
2. 把 `llm_base_url` / `api_key` 换成自备端点。
3. 用 hosts 或本地防火墙把 `openxz.cn` / `pay.openxz.cn` / `newapi.openxz.cn` 指到 `127.0.0.1`。

**优点**：零风险、可逆、10 分钟见效。
**缺点**：不是"软件本体"，换机器/清配置就失效；不同版本键名可能微调。

### L1 — AOT 二进制补丁（中等，推荐）

**做法**
1. 复制 `data/app.so` 为工作副本，记录 SHA-256 基线。
2. 用 `aotopsy` 已有索引定位三个靶点：
   - `sub_70e06c` 的返回值（VIP 检查结果）→ 强制 `bool_true`
   - `sub_6ecd38` 的 8 个写入点 → 强制走 lifetime 分支
   - `sub_6eb6e4` 的 `is_vip` 读取 → 强制 `bool_true`
3. 补丁形式：`MOV r64,[R14+0x90]` → `MOV r64,[R14+0x98]`（改 1 字节 `0x90`→`0x98`）。
4. 替换回 `data/app.so`。

**优点**：改动最小（3～10 字节），不破坏快照结构，两端同一套逻辑。
**缺点**：需要逐点确认上下文，改错会导致崩溃（Dart 无异常保护时直接 terminate）。

### L2 — 本地假后端（最彻底）

自建本地 HTTP 服务，在 hosts 里把 `openxz.cn` / `pay.openxz.cn` / `newapi.openxz.cn` 解析到 `127.0.0.1`，按客户端契约返回：

```json
// heartbeat / app_config / announcement
{"code":0,"data":{...},"msg":"ok"}

// api_vip.php
{"code":0,"data":{"is_vip":true,"vip_status":true,"vip_is_lifetime":true,
                  "vip_expire_time":"2099-12-31 23:59:59","vip_days_left":36500,
                  "vip_device_limit":true,"vip_device_count":1,
                  "member_type":"openwrite","device_limit":true}}
```

**优点**：全链路一致，UI 不打架，`check_update` 也能返回"已是最新"阻止更新覆盖补丁。
**缺点**：要常驻一个本地服务；Android 端 hosts 需 root 或改用 VPN 拦截。

### 推荐组合：**L1 + L2**

L2 兜住启动刷新与错误分支，L1 兜住离线场景（无本地服务时也不掉 VIP）。两者互补，任一生效即可用。

## 6. Android 端差异

| 项 | 情况 |
|---|---|
| AOT 架构 | arm64（需 arm64 补丁，指令形态不同） |
| 额外后端面 | ML Kit 扫码、`flutter_foreground_task` 前台服务 |
| 重打包 | 需要 `apktool` 或直接替换 so + `zip` 重打包 |
| 重签名 | `apksigner` / `zipalign` **本机缺失**，需补装（uber-apk-signer 或 SDK build-tools） |
| 风险 | Android 11+ 需 v2 签名；卸载旧版才能装改签版 |

Windows 端**不需要重签名**：Flutter 引擎不校验 `data/app.so` 的签名或哈希，直接替换即可。

## 8. 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 补丁点位错 → 启动即崩 | 中 | 逐点先备份、单点验证、保留原始 so |
| VIP 多字段不一致 → UI 异常 | 中 | 走 lifetime 分支整体置位，不做单点翻转 |
| `check_update` 拉回官方新版覆盖补丁 | 高 | L2 让 `check_update` 返回无更新；或断网时跳过 |
| 自更新下载 SHA256 校验 | 低 | 更新被阻断后不会触发 |
| Android 签名失效无法安装 | 中 | 补装 apksigner；先卸载原版 |
| 内置 Skill 由服务端下发 | 中 | 首次启动前已落地则保留；否则需先跑一次原版抓取 |

## 10. 明确不做的事

- 不向 `pay.openxz.cn` 发起任何真实订单/支付请求。
- 不伪造支付回调、不生成卡密、不逆向发卡服务端。
- 不把改造产物用于分发或商业用途；仅限本机自用与互操作性研究。
