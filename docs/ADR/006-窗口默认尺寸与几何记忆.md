# ADR-006 窗口默认尺寸与几何记忆

- 状态：已采纳（默认尺寸）／**超出原作**（几何记忆，依据委托方要求）
- 日期：2026-09-28
- 证据：
  - `tools/probe_ow_window.ps1`（原作行为实测，2026-09-28）
  - `tools/probe_win_style.ps1`（writerD 窗口样式与最大化增量实测，2026-09-28）
  - 委托方反馈：「缩放窗口如此困难，每次重启都要重新缩放大小，而且缩放不是默认缩放到
    百分之几，而是直接更改窗口状态为可缩放，但大小和缩放前几乎一致」

## 现象

打包版一启动窗口就几乎占满屏幕；按「最大化」看不出任何变化；每次启动都得手动缩小。

## 根因（两条，均已实测）

1. **默认尺寸等于可用工作区**
   `src-tauri/tauri.conf.json` 原为 `width:1920, height:1032, center:true`。
   实测本机 `workarea = 1920x1032`（1920×1080 屏减 48px 任务栏），
   于是启动窗口 **1936×1041 = 可用区的 102%**，一出生就已经"最大化"了。
   实测 `WM_SYSCOMMAND SC_MAXIMIZE` 前后尺寸只差 **0×7 px** —— 最大化形同虚设。
   附带确认：`WS_THICKFRAME = YES`，即边缘拖拽其实是可用的，问题不在拖拽本身。

2. **完全没有窗口几何记忆**
   Rust 侧对 `resizable/maximize/set_size/position/scale_factor` **零匹配**，
   配置文件里也没有任何几何键；每次启动都按 `tauri.conf.json` 重开。

## 决定

### 1. 默认尺寸改为 1440×900 居中（复刻原作实测值）

原作实测（`probe_ow_window.ps1`）：全新启动 = **1440×900 at (240,66)**，
即 1920×1080 屏的 75%、居中。这才是委托方说的「默认缩放到百分之几」。
改后最大化会从 1440×900 真正变成 1920×1032，视觉变化明确。

### 2. 引入窗口几何记忆（**有意超出原作**）

原作实测**不记忆**：改成 1200×760 后正常关闭再启动，仍回 1440×900，
且配置键数恒为 43、无新增键。因此这一条不是复刻，是委托方明确要求后新增的扩展。

- 记：尺寸 / 位置 / 最大化状态
- 落盘：`%APPDATA%\com.writerd\writerD\window_state.json`
  —— **刻意不写进 `shared_preferences.json`**：真机配置是 43 键的封闭集合（ADR-003），
  窗口几何是 UI 运行时状态而非用户配置，另存可完全不触碰配置键空间。
- 越界保护：`winstate::sanitize()` 把记忆的几何夹回当前屏幕集合；
  外接屏被拔掉、分辨率变小、几何无效时**整组丢弃**，回到 1440×900 居中，
  绝不把窗口恢复到看不见的地方。
- 最大化时记的是"还原后的几何 + maximized=true"，下次启动先还原尺寸再最大化，
  用户取消最大化能回到自己调好的大小。
- 拖拽期间只更新内存基线，**关闭时落盘一次**，避免拖拽产生几十次小文件写。

### 3. 最大化按钮反映真实状态

窗口是 `decorations:false`（自绘标题栏），系统标题栏没有「最大化/还原」按钮，
于是按钮的图标与 tooltip 是用户**唯一**的状态反馈。此前两者都写死为「最大化」，
最大化后按下去仍显示「最大化」。现在由 `src/ui/useMaximized.ts` 跟踪状态并切换
图标（最大化 ⇄ 向下还原）与提示文案，`MainWorkbench` 与 `SettingsScreen` 共用。

### 4. 先就位再显示

`tauri.conf.json` 加 `visible:false`，在 `setup()` 里套用记忆几何后再 `show()`，
避免窗口先在居中默认位置闪一下再跳到上次的位置。
顺序依据：tauri 2.11.6 `app.rs:2531` 先创建配置窗口、`2536` 才执行 `setup`。

## 复验证据

- `cargo test --lib`：`winstate` 12 项纯函数单测（越界丢弃／跨屏接受／拔屏回退／
  过小提升到最小值／超大夹到屏内／出屏平移回屏内／maximized 标志保留／
  旧文件缺字段仍可解析）。
- 真机实拍：启动矩形、最大化增量、拖拽缩放后重启是否恢复（见交接报告 §3.3）。

## 影响面

- 仅影响窗口外壳，不触碰 `src/core/{ai,store,tools}` 与既有数据格式。
- 新增 1 个运行时状态文件（`window_state.json`，非配置、可随时删除）。
- ADR-001 中「1920×1032 = 真机窗口尺寸」的表述已被本次实测推翻，见该文末更正。
