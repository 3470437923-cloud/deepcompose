# ADR-001 画布定标与窗口空白缺陷修复

- 状态：已采纳
- 日期：2026-09-28
- 证据：`reference/shot-writerd.png` 像素采样 + 无头 Edge 布局探针（`.win-frame` 1912×67）

## 现象

打包后的 `writerd.exe` 启动后只有一个 48px 标题栏，标题栏以下全为窗口底色（`#0A0A0F`），三栏界面完全不可见。像素采样：

```
(1000,20)=#0E0E16 标题栏   (1000,47)=#0E0E16   (1000,49)=#0A0A0F   ← 48px 处硬切
(100,500)=(1000,500)=(1800,500)=#0A0A0F        ← 三栏一个都没画
```

## 根因（两条独立缺陷）

1. **`height:100%` 链断在 `.win-frame`**
   `base.css` 把 `.app-shell .fitter/.holder/.win` 都设成 `height:100%`，但漏了 mock 的中间层 `.win-frame`（它自己的 CSS 已被 `convert_mock.py` 作为演示脚手架剔除）。
   百分百高度在「父级高度 auto」上会退化为 auto，于是 `.win` 塌成唯一 in-flow 子元素（`.titlebar`，48px）的高度，
   再被 `.win{overflow:hidden}` 把整个绝对定位的界面裁掉。

2. **`convert_mock.py` 正则误删 CSS**
   原写法 `re.sub(r"body\{[^}]*\}", "", css)` 无选择器边界，误伤选择器里含子串 `body{` 的规则：

   | mock 原文 | 被删后 |
   |---|---|
   | `.b-body{position:absolute;left:0;top:48px;width:1920px;height:984px}` | 残留 `.b-` 碎片，与下一条拼成 `.b- .b-left` → `.b-left` 规则连带失效 |
   | `.b-editor-body{position:absolute;left:0;top:36px;…font-size:15px}` | 残留 `.b-editor-` 碎片，吃掉 `.b-editor-body h1{font-size:19px}` |

## 决定

- `base.css`：补 `.win-frame` 到 100% 规则；`.fitter` 固定为 mock 画布 **1920×1032**（mock 声明值，即真机窗口尺寸），
  由 `App.tsx` 计算 `--fit` 等比缩放并居中。任何窗口尺寸下都与 mock/真机保持同一像素比例。
- `screens.css`：按 `reference/ui-mock.html` L197/L200/L266/L267 原文恢复 4 条规则（逐字，不改尺寸色值）。
- `tools/convert_mock.py`：正则改为 `(?m)^[ \t]*(?:html[ \t]*,[ \t]*)?body[ \t]*\{[^}]*\}`，并要求 `body` 必须位于行首；
  另加**守卫**——转换结果中若出现整行只剩 `.xxx-` 的悬挂选择器碎片即报错退出。

## 复验证据

- 重新生成与手改后的 `screens.css` / 两个 tsx **逐字节一致**（`IDENTICAL`），说明修复可复现。
- 无头探针（改动后）：

```json
{"fitter":[1920,1032],"winframe":[1920,1032],"win":[1920,1032],"titlebar":[1920,48],
 "bbody":[1920,984],"bleft":[220,984],"bchat":[1492,984],"bright":[208,984],
 "bleftBg":"rgb(14,14,22)","bchatBg":"rgb(18,18,26)"}
```

`.win-frame` 由 1912×67 恢复为 1920×1032，三栏尺寸与背景色与 mock 完全一致。

## 影响面

无功能改动；仅修复渲染。`docs/CONTRACT.md` 无需变更。

## 更正（2026-09-28，第四轮实测追加）

本文第 33 行写的「.fitter 固定为 mock 画布 **1920×1032**（mock 声明值，
**即真机窗口尺寸**）」——括号里的推断**是错的**，实测推翻：

- `tools/probe_ow_window.ps1` 实测原作 OpenWrite 全新启动的窗口是
  **1440×900 at (240,66)**（本机 1920×1080 屏，即 75%、居中），
  而 `reference/shot-openwrite*.png` 等 11 张真机截图**全部是 1440×900**。
- `1920×1032` 只是 mock 作者的声明值，恰好等于本机「1920×1080 减 48px 任务栏」
  的可用工作区 —— 这也正是 writerD 一直以近满屏尺寸启动的原因。

该结论与 `docs/CONTRACT.md` §「画布 1920×1032 vs 截图实测 1421×886」记录的
矛盾一致（1440×900 外框 − 边框 ≈ 1421×886 客户区）。

后续处置见 **ADR-006**（默认尺寸改回 1440×900 居中）。本文对 `.win-frame`
高度链缺失、`convert_mock.py` 正则误删这两条**根因分析仍然成立**，未受影响。
