# DeepCompose 首次开源准备

## 当前边界

已创建公共空仓库：https://github.com/3470437923-cloud/deepcompose 。本次仅建立仓库并配置本地 origin；不推送源码、不上传产物、不创建 Release 或 tag。

现有本地工作区包含此前 Windows/macOS 开发的大量未提交改动，必须保留。首次发布不能仅上传旧 HEAD：新平台文件和修复可能尚未进入历史。

## 发布内容

- README：产品定位、Windows/macOS/Linux 平台状态、构建入口与既有数据契约。
- CONTRIBUTING：环境、测试命令、兼容与贡献约定。
- SECURITY：本地配置与模型服务的数据边界、问题报告方式。
- docs/RELEASE-NOTES-1.1.0.md：首次开源 Release 文案草稿。
- docs/LINUX.md：Linux 系统依赖、构建与桌面验收步骤。
- docs/PRE-RELEASE-REVIEW.md：本轮审查、修复证据和剩余发布阻断。
- LICENSE、LICENSE.third-party.txt、THIRD-PARTY-NOTICES.txt 与随附字体许可：保留 GPL-3.0-only 和第三方许可；补充来源及未决边界见 docs/LICENSE-SOURCES.md。Tauri 安装包携带 licenses 资源，Windows 便携包脚本复制三份伴随文本。

## 首次上传的文件范围

源代码、测试、构建脚本、内置技能、图标字体和许可文档需要进入源码仓库。保留 npm 与 Cargo 锁文件。排除 node_modules、dist、src-tauri/target、src-tauri/gen、运行日志、截图、真实作品、配置、会话、快照、网页登录数据和本地 release 包。截图仅使用经核准的虚构示例图。

特别注意：旧历史已跟踪 release/DeepCompose.exe，新增 .gitignore 不会使已跟踪文件自动消失，也不会清理旧历史。本轮不改写历史、不移除用户已有产物。正式上传前推荐从审核后的工作树建立单独的干净开源导出，再逐项检查内容；如果决定保留完整历史，必须先扫描所有提交的凭据、隐私与大型二进制，不能直接推送当前旧历史。

本轮对工作树源码、脚本与文档做了常见 Key/私钥格式检查，命中的是预览占位凭据；这不是完整历史的秘密扫描。不得据此声称所有历史均无秘密。

## 发布顺序（尚未执行）

1. 关闭审查报告中的发布阻断，核对第三方素材来源和许可全文。更新锁文件后，以 Python 3.11+ 执行 tools/collect-notices.py 重建正文，核对其中两份锁文件的哈希。
2. 在原生 Windows/macOS 运行质量闸门和桌面关键流程；Linux 通过原生编译、安装和桌面验收后再标为正式支持。
3. 审核首次上传目录与所有新增文件，确认无真实作品、Key、网页登录数据或无授权素材。
4. 形成最终可复现源码提交。修复若仍沿用 1.1.0 首次开源版本，应避免和已有本地旧包混淆；新发布产物必须对应最终提交。
5. 仅在用户明确授权上传后推送源码，创建对应 tag，再重建并验收发行包。
6. 发布包附 SHA-256、系统版本、架构、第三方许可及源码 tag；使用本地 Release 草稿整理正文。

## 回退

源码和安装包按 tag 对应保留。发布后发现数据风险应撤下受影响下载并说明受影响版本；回退到已核验版本前备份作品与配置，不自动迁移或覆盖用户文稿。Linux 未验收时不附 Linux 二进制，不作兼容承诺。
