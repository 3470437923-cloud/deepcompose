# 资料形态契约（MATERIALS-STYLE）

本文件是**小说资料写法与体量的契约**：写什么、写多长、允许什么符号、过程记录放哪。
`docs/KNOWN-LIMITS.md` 管"已知边界"，`docs/DECISIONS.md` 管"裁决"——本文件管**形态**。

> **判据真源在代码**：预算表与全部阈值在 `src/core/store/style.ts`（`MATERIAL_BUDGETS` /
> `checkMaterial`），由作品校验 `validateProject` 在**打开作品时**逐份体检，提示汇总到主界面状态条。
> 本文件解释"为什么"与"怎么改"；数字若与代码冲突，以代码为准并回来同步本文档。

## 0. 为什么需要这份契约（实测量化，2026-10-03）

以导入作品《李淑珍疑案》为例（17 份资料 / 173,888 字符，全部只读扫描）：

| 症状 | 实测 |
|---|---|
| 单文件失控 | `04-分卷大纲.md` 50,872 字符 = **模板的 205 倍**，占全部资料 29.3% |
| 整体膨胀 | 11 份可对照文档合计为模板体量的 **27 倍**（`人物库` 71×、`追踪-角色状态` 61×） |
| 状态入口被埋 | `00-项目状态.md` 192 行，模板只有 5 个固定节、实物多出 13 节；其中**导入过程叙事占全文件 52%** |
| 装饰符号 | 框线字符 **495**（全在一张 ASCII 架构图里）、`---` 分节线 **379**、`（约N字）` 过程标注 **356**、箭头 360 |
| 表格滥用 | 表格竖线 5,132；叙述性文档也大段用表格 |
| 单一职责失守 | `04` 与 `05` 在 8 个章号上重叠，且 `04` 自称"唯一主本" → 两个真源 |
| **模板本身就在要长内容** | `人物库.md` 模板原本列了 **11 个字段**（含"面对熟人/陌生人/权力差异的表达变化"这类表达层问题），实物就照着写了 11 行/人 → 契约落地时**模板同步瘦到 6 个字段**，表达层问题归 `06-写作规则.md` |

这些不是"审美问题"，是**成本问题**：`00` 是每章开工第一个读的文件，`04+05` 是每次定位场景必读的
文件；膨胀直接抬高每次"最小读取"的成本，也让「格式优先」的节内替换越来越难命中。

**责任划分（重要）**：上表全部是**外部导入一次性写盘**的产物（15/17 份文件 mtime 完全相同）。
应用自己写的部分（`章节摘要.md` 正文）是干净散文。所以本契约要解决的是
**"没有形态约束，所以导入方与应用都不知道该写成什么样"**，而不是"AI 天生爱加符号"。

## 1. 语法白名单（只允许这些）

| 允许 | 用途 |
|---|---|
| `#` `##` `###` | 分节。**分节只用标题层级**，不用 `---` |
| `- 键：值` | 头部字段与条目字段（既有磁盘契约，逐字沿用） |
| `- 文本` | 列表条目；一条事实一行 |
| `\| … \|` | **仅二维矩阵数据**（追踪表、卷章总表） |
| `> 文本` | 仅用于引用正文原文或源文件原话 |
| 行内 `` ` `` | 仅用于路径、文件名、字段名 |

## 2. 禁止清单（每条都给了理由与替代写法）

| 禁止 | 为什么 | 替代 |
|---|---|---|
| 框线/ASCII 图（`─│┌┐└┘`） | 编辑器是比例字体，必然错位；任何编辑都破图；模型无法稳定 `replace` 命中 | 一行一实体：`- 组织：性质 \| 核心人物 \| 手段 \| 渠道` 或表格 |
| emoji、`★☆◆●※` 等装饰符 | 不承载信息，破坏检索与排序 | 去掉；要强调用标题层级 |
| `---` / `===` 装饰分节线 | 分节语义已由标题表达，装饰线只增加 diff 噪声 | `##` 小节标题 |
| 箭头当连接词（`A → B → C`） | 语义含糊、无法检索 | 写成句子：「先 A，再 B，最后 C」 |
| `**粗体**` 当字段标签 | 满屏粗体等于没有重点 | 字段用 `- 键：值`，重点用句子本身 |
| `（约NNNN字）` 等过程标注 | 那是施工记录，不是作品事实 | 删；字数统计交给工具 |
| 导入说明 / 核对证据 / 遗疵 / 待办清单 / 文档归位表 | 流程记录混进内容文件，抬高每次必读成本 | 放 `小说资料/审核/` 的归档文件（见 §4） |
| 「为什么这么设计」式论证 | 属于决策记录，不属于作品资料 | 放归档或 `docs/DECISIONS.md` |

## 3. 体量与职责（预算表）

**字符数为上限，不是目标**：模板体量（`00` 676、`01` 298、`02` 343…）才是理想形态。
超上限会得到一条**警告**（只报告、不改写）；长书按章数等比放宽即可，但**放大的是条目数，不是单条长度**。

| 文件 | 预算（字符） | 允许表格占比 | 一句话职责 |
|---|---|---|---|
| `00-项目状态.md` | 1,500 | ≤25% | 状态入口：每章开工第一个读，只放指针与下一步 |
| `01-开书定位.md` | 2,500 | ≤30% | 类型、读者、一句话故事 |
| `02-核心设定.md` | 3,000 | ≤30% | 世界规则、能力边界、主线 |
| `03-全书大纲.md` | 6,000 | ≤30% | 重大转折与结局方向，**不写逐场次** |
| `04-分卷大纲.md` | 14,000 | ≤50% | **全书节拍表**：每卷目标/卷末新局面 + 每章一行 |
| `05-滚动细纲.md` | 10,000 | ≤50% | **近期施工图**：只放未来 5–12 章的场景细纲 |
| `06-写作规则.md` | 4,000 | ≤30% | 本书写作要求 + 个人文风沉淀 |
| `人物库.md` | 18,000 | ≤30% | 只存稳定特征（**每人 ≤6 个字段行**）；动态状态在追踪表 |
| `章节摘要.md` | 15,000 | ≤30% | 历史归档索引：每章一条简短摘要 |
| `追踪-伏笔.md` | 20,000 | 不判定（矩阵表） | 伏笔矩阵：F 编号 + 埋设/回收章 + 状态 |
| `追踪-角色状态.md` | 12,000 | 不判定（矩阵表） | 角色动态状态矩阵 |
| `追踪-时间线.md` | 10,000 | 不判定（矩阵表） | 事件时间线矩阵 |
| `追踪-资源与权限.md` | 10,000 | 不判定（矩阵表） | 资源与权限当前值矩阵 |
| `追踪-废弃设定.md` | 6,000 | 不判定（矩阵表） | 禁止恢复的旧设定（D 编号） |
| 附加文档（`世界观.md` `风格规范.md` `写作禁忌.md` …） | 8,000 | ≤30% | 用户自建资料（未登记预算，按默认上限） |

**单一职责铁律**：同一事实只在一个文件里维护（与 `novel-writer` 的「职责边界」表同口径）。
**`04` 与 `05` 的分工**：`04` 回答"这本书怎么走"（节拍表，34 章也就 34 行）；`05` 回答"接下来怎么写"（未来 5–12 章的施工图）。
`04` 里不得铺开逐场次细节——那属于 `05` 或归档。

## 4. 过程记录的合法落点

| 内容 | 放哪 |
|---|---|
| 导入过程说明、源文件核对证据、遗疵清单、文档归位表 | `小说资料/审核/导入记录-<日期>.md`（与冷读报告同目录，AI 默认不读） |
| 逐场次全本细纲（超长源材料） | `小说资料/审核/细纲-逐场全本-<日期>.md` 或 `05-滚动细纲.md`（仅近期章） |
| 施工待办、临时决议 | `00-项目状态.md` 的「下一步」一行；多条则放归档并在状态入口留一行指针 |
| 设计理由与裁决 | `docs/DECISIONS.md`（仓库侧；作品里不留） |

## 5. 条目写法（一眼可核）

- **一条事实一行**，句子说完整（主谓完整，不写电报体）。
- 单个条目**不超过 6 个字段行**（`- ` 开头的行；人物库按此判；追踪表按"一行一条目"判）。
- 表格只放二维数据；**一列一个维度**，不要在一格里塞三件事。
- 术语统一：同一实体全书一个写法（人名、地名、组织名）；别名只在其条目里列一次。
- 更新既有条目用**节内替换**，新增条目**追加在文件末尾**（`novel-writer` 的格式优先规则）。

## 6. 存量作品的瘦身流程（治已病，同样有纪律）

1. **先留退路**：写前快照由应用自动落（每次写入前），另**手工导出一份归档副本**（整份原样复制到 `小说资料/审核/`）。
2. **一次一份**，按"超预算倍数"从大到小做：`04` → `人物库` → `追踪-角色状态` → `05` → `00` …
3. **动用户文字前逐份征得同意**（`question`）；用户手改过的格式是最高权威。
4. 每份改完：跑一次作品校验看提示是否清零 → 跑三套闸门 → 提交。
5. **归档不删**：逐场细节是资产，只是不该常驻主路径。

## 7. 改动本契约时

- 阈值改动只改 `src/core/store/style.ts`，并同步本文件 §3 的表（两处必须一起改，判据以代码为准）。
- 新增 14 件套之外的"标准附加文档"时，在 `MATERIAL_BUDGETS` 里登记预算（`tests/store/style.test.ts` 会检查
  每个模板都有预算条目，防止新增文档无预算）。
