# DeepCompose 1.1.4

本版针对写作流程的三类失效做工程约束：文风规则冲突时没有统一口径、交付进度由模型自行宣布、超长工具错误被界面误判为成功。

## 改进

- 系统提示词在项目绑定且盘上存在风格文件时，注入文风优先级声明：本书 `06-写作风格.md`（老作品为 `06-写作规则.md`）覆盖通用技能的同题文风默认，通用技能只补充文件未规定的部分。该声明不改变工具权限、模式限制与安全约束；没有风格文件时不注入。
- `00-项目状态.md` 的正文处理进度写成「待用户确认」但文件里没有复读结论时，写入仍成功并返回警告，要求写明复读过的候选与结论，或把进度改回实际步骤。
- 默认快捷提示词重写：写下一章要求先读风格文件点名的连续场面作为声线样本、动笔前区分主要场面与可合并过场、复读核对声线与场面兑现；细纲续补要求标出必须成立的事实；改稿习惯总结要求单次改动只记观察、不直接晋升为规则。
- 内置技能 `novel-structure-quality-coordinator` 的大纲层级改为全书、粗纲弧段与每份三章的细纲，老作品仍按盘上实际文件工作；章尾检查不再把缺少悬念钩子判为问题。`novel-deslop` 的优先依据文件改为 `06-写作风格.md`。已安装的技能副本按既有纪律不被覆盖，更新需删除对应技能目录后重启。

## 修复

- 工具错误信息超过 4000 字符时附带的截断标记，不再使该次调用被界面判定为成功。
